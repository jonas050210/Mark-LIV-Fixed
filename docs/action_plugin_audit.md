# Action and Plugin Audit

**Audit date:** 2026-09-18

**Compared with:** `origin/main` at `6fc0f4f`

## Scope and method

This is a static security, dependency, secret-boundary, and compatibility audit of the 20 files in `actions/` and the plugin files in `plugins/`.

The audit checked imports, `TOOL`/`PLUGIN` declarations, subprocess and shell calls, file and path operations, browser/GUI automation, network calls, model calls, scheduler integration, config access, and background hooks. No plugin was imported, enabled, started, or called as part of this audit. No API key, token, certificate, personal-memory file, or other secret value was read or copied into this report. No dependency was installed and no plugin configuration was changed.

`take`, `later`, `needs rewrite`, and `skip` are recommendations, not activation commands. A plugin must not be enabled solely because it is marked `take`.

### Recommendation meanings

| Recommendation | Meaning |
|---|---|
| `take` | Suitable for the current scope after normal tests and the existing privacy/user-facing guard are confirmed. |
| `later` | Potentially useful, but defer activation until a focused compatibility or privacy decision is made. |
| `needs rewrite` | Do not activate in the current form. The boundary, validation, confirmation flow, or execution model needs a targeted rewrite and tests. |
| `skip` | Do not treat this file as a runtime feature. It is a template, placeholder, or otherwise not part of the current product surface. |

## Executive summary

### Recommended for the current scope

- `actions/reminder.py`: bounded local scheduling with sanitized message text and least-privilege Windows task settings.
- `actions/system_monitor.py`: read-only metrics; no subprocess invocation in the monitoring path.
- `actions/weather_report.py`: read-only browser search with URL encoding and no local file/system mutation.
- `actions/web_search.py`: useful read-only search/fallback path, provided external results remain untrusted model input.
- `actions/background_monitor.py`: useful as an explicitly user-configured helper; it stores topics and performs daily DDG checks.
- `plugins/document_review.py`: pure result validation/rendering with no direct network, file, or secret access; legal-advice limitations must remain visible.

### Defer

`computer_settings`, `file_controller`, `flight_finder`, `proactive`, `screen_processor`, and `youtube_video` have bounded or mostly read-only use cases, but need explicit privacy/compatibility decisions and targeted tests before activation.

### Do not activate yet

`browser_control`, `code_helper`, `computer_control`, `desktop_control`, `dev_agent`, `file_processor`, `game_updater`, the current `open_app.py`, `send_message`, `chat_takeover`, and `telegram_remote` cross a real OS, browser, file, code-execution, messaging, or remote-control boundary without a sufficiently strong common confirmation and isolation model.

The current checkout still contains the old `actions/open_app.py` with `shell=True`. The safer change is in the still-open PR #5 (`65b7ad2`), not in `origin/main`; it should not be duplicated or assumed merged.

## Plugins

The runtime loader deliberately skips files whose names start with `_`; therefore `_template.py` and `__init__.py` are not discovered as runtime plugins. The loader does import every other `*.py` plugin during discovery before the enabled flag is checked. That is a runtime import behavior to keep in mind: “disabled” prevents tool declarations, `run()`, and `on_launch()`, but is not the same as “never imported.” In addition, `memory.config_manager.get_plugin_enabled()` currently defaults an absent setting to `True`. On a fresh configuration, every valid discovered plugin is therefore exposed to the Live tool declarations unless `plugins_enabled` is explicitly populated with `false`; this conflicts with the audit constraint that plugins must not be activated blindly.

## Findings that must remain visible before activation

1. **Plugin discovery and defaults are not inert.** `core.plugin_loader.discover_plugins()` imports every non-underscore Python plugin to validate it. Disabled plugins are not exposed to the model and do not run, but import-time code still executes. `get_plugin_enabled()` also defaults missing entries to `True`, so a fresh configuration exposes all valid plugins by default. A stricter design should default to opt-in for high-risk plugins and use a manifest/static metadata pass before importing optional plugins.
2. **Model output is an untrusted control input.** This applies especially to browser, computer, desktop, code, file, game, messaging, and remote-control paths. Web pages, documents, screenshots, transcripts, and Telegram messages can all carry prompt-injection text.
3. **Local confirmation is not consistent.** `computer_settings` protects only selected irreversible controls. File changes, external messages, browser forms, game installs/shutdowns, and generated-code execution need separate confirmation and/or a constrained capability mode.
4. **A “home directory” boundary is not a complete sandbox.** Resolve and re-check every derived path, account for symlinks and races, and reject archive entries that escape the destination.
5. **Secrets stay outside this report and outside Git.** Keep API keys, bot tokens, OAuth files, certificates, WhatsApp session data, long-term memory, and `.env` files out of commits and logs. The audit did not read their values.

## Local LLM path

The isolated local LLM client in `core/llm_client.py` routes between Ollama and generic OpenAI-compatible local servers (LM Studio, LocalAI, Jan, llama.cpp, vLLM), selected by `llm_provider` in the local configuration. Its chat, text-only, warmup, model-list, and streaming requests all follow that selection. No hosted text provider is configured, enabled, or auto-selected: an unrecognised `llm_provider` value falls back to local Ollama, and the local path sends no credential to the server it talks to. No provider key was read during this audit, and no local configuration was created or changed.

`call_llm_text()` now follows the configured provider instead of always posting to Ollama's `/api/chat`. This repair is intentionally limited to the reusable local LLM client. The running assistant's primary path in `main.py` remains the existing Gemini Live audio/tool loop (`models/gemini-3.1-flash-live-preview`); it was not redirected to `core.llm_client`, because that would require a separate, agreed STT/TTS and audio-session design. Gemini API access in `main.py` and `core/gemini.py` is therefore deliberately unchanged.

## Suggested next gate

Keep all `needs rewrite` actions/plugins disabled and do not install optional plugin dependencies just to test them. The local LLM client repair does not activate any action or plugin. The next implementation pass should define a small capability/confirmation policy, then add isolated tests for the specific boundary fixes rather than enabling the high-risk tools wholesale.

### Findings resolved since the audit

1. **`code_helper.py` — `args` declared as `STRING` but consumed as a list.** This was recorded as a live risk in the Actions table above: `interp + [str(path)] + (args or [])` raised `TypeError: can only concatenate list (not "str") to list` whenever the model answered with a single string, which killed the whole run/build path. `args` is now declared as an `ARRAY` of `STRING`, and a new `_as_arg_list()` normaliser accepts every shape the model actually sends — a list, a tuple, a plain string (split with `shlex.split`, so `--out "my file.txt"` stays intact), a number, or nothing. Each element is stripped, matching every other string in the module.
2. **`weather_report.py` — read a parameter it had never declared.** The handler read `parameters.get("time", "today")`, but `time` was absent from `properties`, so the model was never offered it and the branch was dead. `time` is now declared as an optional `STRING`; `required` still lists only `city`. The 32-character description ("Gives the weather report to user") is replaced with one that states when to use the tool and when to use `web_search` instead, and `parameters` is now type-checked before use.
3. **`core/llm_client.py` — docstring claimed callers that never existed.** It said "Used by planner, executor, error_handler, code_helper, dev_agent." No module in the repository imports `llm_client` (verified by scan: zero importers). The docstring now says that plainly and describes what the client actually is: the standalone local-LLM path for callers that want Ollama or an OpenAI-compatible local server instead of a hosted model. The Local LLM path section above remains accurate.

4. **`open_app.py` — `shell=True` on both Windows launch paths.** `_launch_windows` checked `shutil.which()`, threw the result away, and passed the model's raw string to `Popen(app_name, shell=True)`; the protocol-handler path was worse, building `f"start {app_name}"`. A name of `ms-settings: & calc.exe` would have executed `calc.exe`. Both are gone. Protocol handlers now match an anchored pattern (`^[A-Za-z][A-Za-z0-9+.\-]*:$`) and go to `os.startfile()`, which hands the string to the shell as something to *open* rather than a command line to parse. Executables are resolved to an absolute path by `shutil.which()` and launched as an argument vector. An unresolvable name falls through to the existing Start-menu search instead of reaching a shell.
5. **`dev_agent.py` — `shell=True` with a model-derived path.** `_open_vscode` ran `Popen([cmd, str(project_dir)], shell=True)`, and `project_dir` is `PROJECTS_DIR / project_name` straight from the model. Windows permits `&` in a folder name, so a project called `x & calc.exe` launched calc.exe. It now prefers the real `Code.exe`, which CreateProcess runs directly with no shell at all. A `.cmd` wrapper cannot be run that way, so that path goes through an explicit `[ComSpec, "/c", wrapper, dir]` vector and is **refused outright** when the directory contains any of `& | < > ^ % " '` — refusing beats sanitising and hoping. This matters on Windows 11 specifically, which is where VS Code is normally installed as `code.cmd`.

### Known gaps deliberately left open

* **Four existing actions still read `parameters.get(...)` without an `isinstance` guard** — `file_processor.py`, `reminder.py`, `youtube_video.py` and (until this pass) `weather_report.py`. A non-dict argument raises `AttributeError`, which `registry.run()` already catches and turns into a tool-failure string, so the app survives; only the reply is unhelpful. `weather_report.py` was fixed because it was being edited anyway. The other three were left alone to keep this change reviewable — worth a separate, tiny pass.
* **Seven existing `TOOL` descriptions fall short of the 120-character rule the new actions follow.** Measured: `reminder` 43, `code_helper` 52, `flight_finder` 52, `desktop` 62, `send_message` 73, `file_controller` 99, `computer_control` 104. This is a routing-quality issue, not a bug — the model picks tools partly by description, and a five-word description loses against a precise one when two tools could plausibly serve the same request (`reminder` versus the new `timer` is exactly such a pair, which is why `timer`'s description spells out the difference). `weather_report` was the eighth and was improved in passing; these seven are unchanged.
* **`computer_settings.py` still uses `shell=True` twice** (the Linux brightness fallback around lines 199 and 228). Unlike the two above, neither is injectable: the command string is a compile-time constant containing no model or user input, and both branches are Linux-only (`elif _OS == "Linux"`), so a Windows machine never reaches them. It is worth cleaning up for hygiene — the embedded `python3 -c` inside a shell substitution is unpleasant to read — but it is not a security defect and rewriting a brightness path that cannot be tested here was judged the larger risk.
* **`dashboard/server.py` writes a temporary `.bat` at runtime** (`tempfile.mkstemp(suffix=".bat")`) to run `netsh` and `Set-NetConnectionProfile` elevated for the remote-dashboard firewall rule, then launches it with `ShellExecuteW(verb="runas")` and `subprocess.run([bat_path], shell=True)`. This is the only place in the repository that produces a batch file. It is pre-existing, outside `actions/`, and it needs a real Windows machine with UAC to verify — replacing it would mean elevating a single `powershell.exe -Command` that performs all three steps, keeping one UAC prompt and dropping the file entirely. Flagged rather than changed, because a broken elevation path silently costs the phone dashboard its network access.
* **`open_app` and `dev_agent` were fixed blind.** The sandbox is Linux, so neither Windows launch path could be executed here. Both fixes were verified by simulating the platform: `sys.platform` set to `win32`, `shutil.which` / `subprocess.Popen` / `os.startfile` replaced with recording fakes, and 54 assertions covering the URI pattern, path resolution, argv shape and eight injection payloads per function. The Windows-native notification tier was verified the same way, including the `NOTIFYICONDATAW` field layout (all 15 offsets match the documented x64 layout; note that `ctypes.wintypes` measures differently on Linux — `DWORD` is 8 bytes there against 4 on Windows, `WCHAR` 4 against 2 — so the structure is deliberately defined *inside* the platform gate). Real-machine confirmation is still the outstanding step.

## Addendum — action audit remediation + two new actions (2026-09-19)

Work on `arena/01a0b859-mark-liv-fixed`. `actions/` now holds 25 files: 20 with a `TOOL` dict (18 previous + `app_inventory` + `screen_vision`) and 5 helpers. New shared module `core/app_finder.py` (alias/discovery/launch engine behind `open_app`, `app_inventory` and `send_message`). Files this audit names that do not exist in this tree: `flight_finder.py`, `weather_report.py`, `code_helper.py`, `dev_agent.py`, `browser_agent.py`, `core/jev/`. No dependency was added; no secret value was read while writing this.

### Findings resolved since the audit

1. **`computer_settings.py` — the two `shell=True` brightness fallbacks are gone.** Both xrandr paths are now a `_xrandr_brightness` helper using an argument vector. `shell=True` now appears only in comments.
2. **`dashboard/server.py` — the `shell=True` on the firewall path is gone.** The try-direct run is now `["cmd.exe", "/c", bat_path]` as an argument vector. The `.bat` file itself (mkstemp-created, constant rule names, port always the int constant 8000/8001) and the elevated ShellExecuteW/`runas` fallback remain by design: replacing the elevation path blind, on Linux, risks silently breaking the phone dashboard's network access — the same judgement the previous addendum records.
3. **`file_controller.py` — `rename` validated the source but not the destination.** `new_name="../../..."` moved files out of the home jail. `new_path` is now checked with `_is_safe_path` before the rename (verified: traversal denied, normal rename works).
4. **`file_processor.py` — no path jail, Zip-Slip extraction, `mktemp`, format traversal.** Entry paths and archive destinations are now confined to home/tempdir; archives unpack through a `_safe_unpack` that refuses absolute/`..` members, skips symlinks/devices, and resolves every entry against the destination (verified against hostile zip + tar); `tempfile.mktemp` became `NamedTemporaryFile`; `_output_path` keeps only the final path component and image/audio/video `convert` validate `format` against `[A-Za-z0-9]+` (before, `format: "../../x"` escaped the output directory). Code `run` uses `sys.executable` instead of bare `"python"`.
5. **`game_updater.py` — `shutdown_when_done` had no confirmation gate.** Auto-shutdown now goes through `core/confirm.py` like the settings power actions (fail-closed with no UI bound; verified no watcher thread spawns headless). Windows scheduling no longer attempts `SYSTEM`/`HIGHEST` (a scheduled user-writable script must not run as SYSTEM); schedule hour/minute are clamped; the launchd plist XML-escapes its paths.
6. **`browser_control.py` — any URI scheme reached the browser.** `_normalize_url` passed `file://`, `javascript:` and friends into headed Playwright and native launch, with `get_text` able to read the result back into model context. Only `http(s)` passes now (plus a `javascript:`/`data:`/`file:` prefix check for scheme-without-`//` forms); `localhost:8000`-style host:port pairs are no longer mangled.
7. **`summarize.py` — SSRF via redirect.** `requests` followed redirects, so a public link bouncing to `169.254.169.254` bypassed `_blocked_host`. Redirects are now walked by hand (max 5) with scheme/host re-validation per hop (verified live: legit chain followed, evil redirect refused, loop capped).
8. **AppleScript/PowerShell quote injection (3 sites).** `computer_control._focus_window` interpolated the window title into PowerShell and AppleScript source; `computer_settings.set_wallpaper` (macOS) and the already-fixed `desktop.py` wallpaper interpolated the image path. Titles/paths containing `"` are now rejected, matching the desktop fix.
9. **`send_message.py` — unknown platform names reached `Popen` on Linux.** The platform fallback passed model text to a bare `[app_name]` exec. Only plain executable names (`[a-z0-9][a-z0-9._+-]*`) may reach it now; paths, spaces and flags fall back to `gtk-launch`-only.
10. **`reminder.py` — scheduler quoting.** Windows XML and macOS plist paths are XML-escaped; the Linux `at` command is `shlex.quote`d (`at` runs stdin through `/bin/sh`, so a space in the home path could split the command).
11. **`youtube_video.py` — `region` crash + injection, `summarize` ignored its URL.** Explicit `region: null` crashed on `.upper()` and the value landed raw in a query string; it is now coerced and clamped to a 2-letter code. `summarize` always popped the paste dialog even when the model had the URL; it now accepts the `url` parameter first (schema updated).
12. **`notify.py` — macOS tier added.** The audit records "deliberately no AppleScript path on macOS ... so macOS falls through to the log". A tier was added anyway (`display notification` via argv, quotes stripped — the same sanitisation the reminder scheduler uses), because a notification tool that silently logs on one platform contradicts its own description. Windows/Linux behaviour unchanged.
13. **`screen_vision.py` (new) — failed captures burned the cooldown.** `_mark_called()` ran before the capture attempt, so one failure locked out retries; the mark now happens inside `_capture()` on success only. Capture errors are logged technically but answered in one friendly spoken sentence.
